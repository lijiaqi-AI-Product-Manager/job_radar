# 招聘日历说明

日历条目按「用户点进去能得到多少信息」分三档，**`notes` 字段里会写明**：

| 档 | 特征 | 怎么识别 | 2026-10-24 数量 |
|---|---|---|---|
| **A 招聘专页** | 官方招聘/校招页面，有岗位列表或网申入口，通常也有公开 JD | `jd.status: official_page`，`notes` 无档位前缀 | 243 |
| **B 公众号公告** | 官方公众号推文（带发布日期） | `source.type: wechat` | 4 |
| **C 仅官网首页** | 只找到官网，没有独立招聘页 | `notes` 以「【仅官网首页】」开头 | 175 |

C 档是为了保证「500 家覆盖」不出现空洞：宁可给一个能点开、能自己找到「人才招聘」的官方入口，
也不要留一条假链接。要只看高质量入口时，按 `jd.status=official_page` 或 `notes` 前缀过滤即可。

## 条目从哪来

| 来源 | 说明 |
|---|---|
| 人工（`origin: manual`） | 从官方招聘页 / 官方公众号 / 政府平台逐条核实，`source` 里带名称、链接、日期 |
| 自动（`origin: auto`） | 由岗位数据按「源 × 项目类型 × 届次」聚合，带 `open_jobs`（当前在招数）与 `observed_from/to`（观测窗口，**不是网申起止**） |

## 字段规则（完整规范见 [CALENDAR-FORMAT.md](CALENDAR-FORMAT.md)）

- **有公开 JD**：`jd_status=linked`（关联数据层岗位）或 `official_page`（官方 JD 页链接）
- **JD 被挡**（验证码/登录墙）：`jd_status=blocked`，只发日历信息，并在回答末尾原样带一句
  `{公司名}希望你去他们的招聘页逛一逛哦~`
- 来源没写的字段一律留空，**不推测**（例如不根据往年推今年截止日）

## 怎么用

```bash
jobradar calendar --group 阿里巴巴 --type 秋招 --grad-year 2027   # 某集团某批次
jobradar calendar --type 秋招正式批 --open-on 2026-10-24           # 今天还能投的
jobradar calendar --company 飞猪                                   # 具体公司/产品线
```

每条结果都带 `source`（来源）与 `as_of`（核实日期），回答用户时应当注明，例如
「据字节跳动校园招聘官网（核实于 2026-10-21）」。
