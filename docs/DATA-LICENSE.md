> 「具体措辞由项目维护者在发布前确认」）。代码许可是 MIT，见 `LICENSE`。

## 事实前提

- 数据集里的**岗位信息**（标题、职责、要求、投递链接）来自各公司**官方招聘页**的公开内容，
  权利归原发布方；
- 本项目做的是**索引、结构化与检索**，不代替官方渠道，也不对岗位内容做再授权；
- 数据里**不含**投递人信息、cookie、token。

## 三个可选方案

| 方案 | 措辞要点 | 优点 | 风险 |
|---|---|---|---|
| **A. 仅索引声明（推荐，最稳）** | 「本库对公开岗位信息做索引与结构化，不主张对原始内容的权利；转载/再分发请遵守原发布方条款并保留链接」 | 与现状一致，最不容易越界 | 别人二次分发时责任不清，需要自己判断 |
| **B. 数据库权利 CC0/ODbL** | 对「整理后的结构化数据」声明 ODbL（署名 + 相同方式共享） | 二次利用规则清晰，社区友好 | ODbL 的「相同方式共享」可能挡住商业使用；仍需遵守原始站点条款 |
| **C. 仅限非商业** | CC BY-NC 4.0 | 保护原作者利益 | 限制最严，推广时会被企业用户排除 |

## 建议

**A + 一段「你能做什么」的说明**（不需要额外许可声明）：

- ✅ 你可以：本地查询、写工具、做分析、在文章里引用并附原链接
- ⚠️ 你需要：遵守各公司招聘页的使用条款；不要把数据当作官方信息源对外承诺
- ❌ 请不要：把数据包装成「官方招聘平台」；批量转售岗位信息

## 需要维护者确认的三件事

1. 选 A / B / C 哪个（默认建议 A）
2. 是否在 README 放一句「数据许可」摘要（现在只有代码的 MIT）
3. 是否需要在 Release 说明里加同样的声明

确认后把最终措辞写进 `COMPLIANCE.md` 的「数据许可」一节，并删掉本文件的「草案」状态。
