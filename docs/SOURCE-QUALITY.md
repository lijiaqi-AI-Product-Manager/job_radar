# 来源重合与历史记录

岗位记录保留原来源、雇主名称和实际观测时间。来源暂停采集后，历史记录继续分发；暂停采集不等于岗位已关闭，也不能据此确认当前可投。

查询返回的 `availability_label` 用中文说明状态，`source_warnings` 列出需要核实的限制。`source_tenant_peers` 表示配置中同一招聘租户还登记在其他来源下，岗位可能重合；不要把这些来源的数量直接相加。表格输出也显示状态和同租户提示。客户端中的来源目录随软件发布，不代表实时的访问许可或采集健康度。

## 相同租户与相同记录

- 北森按实际请求主机识别租户；大易按SU标识识别，白标域名不会成为另一个租户。招聘类型完全分离的项目允许分别登记。
- 启用配置中不允许重复采集同一个租户的同一招聘类型。暂停重复配置不删除历史记录，也不生成岗位关闭事件。
- 不同租户出现相同岗位，只能作为待核实线索。集团、子公司、专项项目可能部分重合，不能自动推导同一雇主或整站重复。

运行离线只读检查：

```bash
uv run python scripts/find_duplicate_tenants.py --db <数据目录>/jobs.db --csv <报告目录>/source-overlaps.csv
```

工具比较同平台的岗位编号、标题、城市集合、类型、届次、学历、部门、批次及截止日。默认至少3条重合，且至少覆盖一侧90%的可见记录，才列入候选；两侧比例分别报告，避免把包含关系说成全量相同。快照日期、样本编号和统计范围随结果给出。相同编号在不同平台不构成证据。

`same_configured_tenant` 只表示配置明确声明的相同租户；`record_overlap_candidate` 仍需核对原站及雇主归属。工具不写数据库、不自动合并公司、不改变来源启用状态，也不会减少公开数据条数。退出码1表示存在启用租户冲突或检查未完成；岗位重合候选本身不作为自动停用依据。
