# 岗位与正文的观测时间

岗位列表和职位描述分别记录观测时间。`last_seen` 表示最近一次在来源列表中看到记录；详情、岗位对比和全文检索结果的 `text_observed_at` 表示正文最近一次采集所属批次的时间。两者不同是正常情况，投递前应核对原始招聘链接；缺少正文时该时间为空。

`stats.jobs.jd_observation` 报告正文在48小时内的观测数量、较早观测数量和时间范围。`data_as_of` 是最近一次成功来源观测的时间，不代表所有岗位或正文均在该时刻重新读取。

`source_enabled: false` 表示客户端来源目录已停用该入口。查询保留其历史岗位，状态为 `unconfirmed_disabled`；即使上一成功观测尚不足48小时，也不能表示当前已确认可投。停用不改变原始岗位状态；已下架、已到期仍分别显示 `closed`、`expired`。

大易来源每轮完整读取配置范围内的岗位列表。只有同一来源、同一岗位ID、标题、招聘类型、发布日期和学历一致，且已有可用正文时，才可复用最多168小时的原文。新岗位、元数据变化、无效正文及超出期限的缓存均需读取详情。列表失败不会使用缓存冒充成功的完整抓取。

详情读取失败时保留已有正文及其原观测时间，不能标为本次新读。完整列表中的岗位状态继续按既有截止日和连续缺席规则处理；正文失败不能被用来推断岗位下架。

该策略减少重复读取，保持源限速。正文复用、列表刷新及软件安装版本分别验证，不能把高覆盖率或测试通过解释为每条岗位都经过实时人工核实。

## 实习聚合来源的正文复用

实习僧列表每轮完整读取，明确属于其他公司的记录不请求详情。标题前后文、明确城市和学历等与既有记录一致时，可在48小时内复用已核验正文，保留原`fetched_at`；过期、未来时间或明确字段变化会重读详情。列表字体字符只用于与既有标题的未知位置比较，不还原或猜测字符。

列表中途为空、重复分页或条数不足均不能视为完整采集。详情读取的预算中断直接上抛，失败来源不改变岗位状态；仅有母品牌名称也不能证明岗位归属某个子公司。

实习列表先快速读完再读取详情，减少长时间逐岗读取期间排序变化造成的跨页重叠。整页重复或没有新记录仍失败；局部重叠按岗位ID去重，数量核验区分返回行和独立岗位。

## 未完成来源的详情进度

采集端将新读到的规范化正文独立保存为临时进度，绑定来源主体、配置与适配器版本；不保存请求、会话或原始响应，不进入公开快照。预算中断或拒收不改变岗位库和正文库，下一轮仍先完整读取列表，再按既有时效和元数据规则复用详情，原观测时间不刷新。

每日工作流独立恢复和保存该进度，单源最多64MiB、单条2MiB；失效进度不作为事实使用。辅助缓存失效时继续正常采集，质量门禁与失败保留历史的规则不变。
