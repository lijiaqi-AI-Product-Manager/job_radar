# 发布门槛与自检

把「能不能发」变成可执行的检查，而不是拍脑袋。

```bash
uv run python scripts/release_check.py --home ~/.jobradar
```

逐项输出 PASS/FAIL，退出码非 0 表示未达标。

## 门槛（`scripts/release_check.py` 的 `GATES`）

| 项 | 门槛 | 为什么 |
|---|---|---|
| 数据源覆盖 | **≥ 160 / 500** | 有岗位数据的公司才谈得上「岗位查询」 |
| 日历覆盖 | **≥ 450 / 500** | 抓不到 JD 的公司也要能告诉用户「去哪投、什么时候」 |
| 校园岗城市覆盖 | **≥ 20%** | 用户第一诉求是「某个城市有什么岗」。定 20% 是因为体量最大的几个北森新版租户不返回城市（三次独立验证，见 `docs/recon/beisen.md` §6），60% 在当前源结构下不可达（见下方延伸目标） |
| JD 正文覆盖 | **≥ 95%** | 没有正文就没法对比、没法全文检索 |
| 日历字段完整度 | **≥ 37%** | 人工条目里「11 个必填字段至少填 7 个」的占比（字段规范见 `CALENDAR-FORMAT.md`） |
| 日历按公司完整 | **≥ 60%** | 每家公司至少有一条完整条目——用户按公司查时能拿到届次/方向/城市 |
| 发布文档 | README / CHANGELOG / COMPLIANCE / LICENSE 齐全 | 正式版要给用户交代许可证与合规边界 |

## 干净环境安装验证（2026-10-24 复核）

用 `uv build` 的 wheel 建全新 venv（不依赖仓库），跑完整用户路径：

| 步骤 | 结果 |
|---|---|
| `jobradar --version` | `jobradar 1.0.1` |
| `jobradar update` | 4 秒（全新环境），三个库走 GitHub；**再次运行 0 下载**（增量） |
| `JOBRADAR_MIRROR=gitee jobradar update --force` | 80 秒，自动拼接 2+3 个分片 |
| `jobradar doctor` | 三个库齐全，未过期，`jd_text_match = 1.0` |
| `jobradar search --company 复星 --type campus` | 正常返回岗位 |
| `jobradar calendar --group 京东` | 返回条目，`jd_status=blocked` 带提示语 |

## 发布流程（每次发版）

1. `uv run pytest` + `uv run ruff check src tests scripts` 全绿；
2. `uv run python scripts/release_check.py --home ~/.jobradar` 全 PASS；
3. 更新 `CHANGELOG.md`；
4. 改版本号（`pyproject.toml`）→ `uv lock` → `uv build` 确认 sdist < 5MB（CI 已守卫）；
5. `git tag vX.Y.Z && git push origin vX.Y.Z`；
6. 建 GitHub Release（正文用本版 CHANGELOG），必要时配 PyPI（见 `PUBLISHING.md`）；
7. 发完跑一次 `jobradar update` + `doctor`，确认 Release 资产可下载、数据未过期。

## 已知缺口

- **城市**：北森新版列表接口 `LocNames` 恒为空，标题/部门只能补回一部分；已接入的自带城市源（hotjob、北森旧版、部分北森新版租户）贡献了主要覆盖。
- **网申时间**：只有约 5% 的官网公开写起止日期；公众号被微信风控挡住，不自动化。
- **届次**：校园岗 39.7% 有；其余来源未提供，JD 里也没有。

## 延伸目标（未纳入发布门槛，持续追）

| 目标 | 现状（2026-10-24） | 卡点 |
|---|---|---|
| 数据源覆盖 ≥450/500 | **161/500** | 剩下的公司大多不用可枚举的 ATS：银行券商自研门户、央企加密网关（中国建筑 `hcm_param`）、WAF 412（国家电网/中国石油）、外企 Workday（已扫 67 家，只有阿斯利康/辉瑞命中且在中国有岗位）。可枚举通道跑过 200+ 组，命中率个位数 |
| 校园岗城市 ≥60% | **29.6%** | 城市只存在于 hotjob（100%）、北森旧版（100%）和部分北森新版租户；体量最大的几个新北森租户恰好没有城市 |
| 日历字段 ≥60%（人工条目口径） | **38.0%** | 162 条只有官网首页（175 个首页扫描只找到 3 个招聘页）、32 条 Moka 加密、4 条飞书签名 |

结论：这三个数字由**数据源的平台结构**决定，不是解析 bug；提升只能逐个攻克自研门户或逐租户渲染。
