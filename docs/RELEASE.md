# 发布门槛与自检

本次持续目标是固定 1,655 家公司的合规配置覆盖至少 80%（1,324 家）。历史发布质量门禁与这个目标分别验收；测试通过、旧门禁通过都不代表最终交付完成。当前进展见 [DELIVERY-PROGRESS.md](internal/DELIVERY-PROGRESS.md)。

## 验收命令

```bash
uv run ruff check .
uv run pytest
uv run python scripts/check_docs_links.py
uv run python scripts/check_compliance.py
uv run python scripts/release_check.py --home <数据目录>
uv run python scripts/coverage_report.py --json --min-coverage 0.8
```

真实数据检查需要包含 jobs.db、jd_text.db 和 calendar.db 的目录。缺数据的 SKIP 不能作为通过。覆盖目标命令当前退出 1：919/1,655 = 55.53%，还需 405 家；历史受限目标保留在分母，停用源不计覆盖。

## 11 项既有质量门禁

门槛来自 `scripts/release_check.py` 的 GATES，未因本次验收放宽。配置覆盖不是当天有岗位的公司数。

## 本地提交与对外发布

1. 完成回归、ruff、文档链接、离线合规核验，记录真实数据检查及覆盖目标的独立结果。
2. 更新 CHANGELOG 与进度记录；构建 wheel / sdist，确认 sdist <5 MiB、新迁移和包内数据齐全。
3. 在独立环境安装构建出的 wheel，验证 CLI / MCP 启动与包内映射；本地提交开发成果，不把未达标目标描述成已完成。
4. 本次用户只授权本地提交，**未授权 GitHub 推送、tag、GitHub Release 或 PyPI 发布**。对外发布须有明确授权，并满足最终验收。
5. 获得发布授权后，版本只改 `src/jobradar/__init__.py`（Hatch 动态读取），锁定依赖并重建，按 [PUBLISHING.md](PUBLISHING.md) 执行；发布后再验证真实下载与增量更新。

缺失的日期、城市、届次或学历保留缺失，不为通过门禁推断或编造。逐站 robots / 条款与源归属核查不能由离线检查替代。
