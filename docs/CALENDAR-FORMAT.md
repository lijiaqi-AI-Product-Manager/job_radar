# 招聘日历条目格式（长期要求，2026-10-23 用户确认）

> 这份文件是**长期规范**：以后新增/修改日历条目、写抓取脚本、做验收，都以这里为准。
> 代码里的强制项见 `janitor/taxonomy/calendar.yaml` 与 `tests/test_calendar.py`。

## 一条日历 = 一个「公司 × 届次 × 项目类型」的招聘活动

每条必须包含下面这些内容（用户原话："我要求的日历是必须包含以下内容的"）：

| 字段 | 含义 | 示例 | 代码字段 |
|---|---|---|---|
| 集团 | 目标名单里的集团名 | 阿里巴巴 | `group_name` |
| 具体公司/具体产品 | 具体法人或产品线（**集团 ≠ 具体公司**） | 飞猪旅行有限公司 / 飞猪旅行 | `company` / `product` |
| 届次 | 哪一届 | 27届 | `grad_year` |
| 项目类型 | **必须分条目**：寒假 / 暑假 / 实习 / 春招 / 秋招 / 提前批 / 校园大使 / 校招 / 社招 / 兼职 / 线上 | 秋招正式批 | `project_type` |
| 方向 | **track 级，可多条**：方向 + 具体岗位名 | 技术类-算法/后端/客户端；产品类-AI产品 | `tracks` |
| 网申时间 | 起止 | 2026-08-03 ~ 2026-12-31 | `apply_start` / `apply_end` |
| 城市 | 工作城市 | 北京/上海/深圳/杭州/成都 | `cities` |
| 投递入口 | 官方投递链接 | join.bytedance.com/campus/position… | `apply_url` |
| 来源 | 官方来源，公众号要带发布日期 | 字节跳动招聘公众号 2026-08-03 推文 | `source`（type/name/url/date） |
| 数据时间戳 | 这条数据是什么时候看到的 | 2026-10-21 | `as_of` |

## JD 规则（用户明确：不要求 100%）

- **有公开 JD**：必须挂上 —— 关联数据层的岗位（`jd_status=linked`）或官方 JD 页链接（`jd_status=official_page`）
- **JD 被挡**（验证码 / 登录墙）：只发日历信息即可，并在返回结果末尾加一句
  `{公司名}希望你去他们的招聘页逛一逛哦~`（`jd_status=blocked`，代码见 `queries.BLOCKED_HINT`）

## 覆盖要求

- **500+ 家公司全部要有日历条目**（按上面格式整理或查询出来，一家都不能少）
- 拿不到 JD 不影响覆盖；**日历字段拿不到就留空**，不编造（红线）
- 已知不可做的公司写进 `targets/top_companies.yaml` 的 `blocked`，写明原因与侦察文档

## 字段为空时的约定

- 空 = 网站没有公开该信息（不是"没有这项招聘"）
- `jd_status=blocked` 的条目必须带提示语；`jd_status=none` 表示找不到公开 JD 页
- 每条都要有 `as_of`，用来告诉用户数据新鲜度
## 字段完整度的现实上限（2026-10-23 实测，355 个页面渲染 + 486 个页面 HTML 扫描之后）

三个口径（`release_check` 都会打印）：

| 口径 | 数值 | 说明 |
|---|---|---|
| 纯人工条目 | 38.0%（187/492） | 最严格：没有数据源的 343 家只能靠人工条目 |
| 全部条目 | 74.9%（1026/1370） | 用户实际查到的所有日历行 |
| 按公司 | **60.2%（359/596）** | 每家至少有一条完整条目 |

为什么人工条目上不去（不是没做，是页面上确实没有）：

| 卡点 | 条目数 | 说明 |
|---|---|---|
| C 档只有官网首页 | 162 | 首页不写届次/网申时间/城市；对 175 个首页做过「找 careers 链接」扫描，只找到 3 个招聘页（其中 1 个是第三方站点，红线不能用） |
| Moka 租户 | 32 | 岗位数据 AES 加密；渲染 35 个页面，**0 个**能读出岗位名，只能读到城市 |
| 飞书 ATSX | 4 | 需要前端 `_signature`，不逆向 |
| 网申时间 | 全网 | 只有约 5% 的站点在「招聘公告」里写起止日期；公众号推文是最可靠的来源，但微信对数据中心 IP 返回验证页，Actions 抓不到 |

已用到的替代通道（都是页面明写、可复核的）：

1. **数据层投票**：该公司 948/952 个岗位都是 2027 届 → 回填届次（27 条）
2. **JD 明写工作地点**：`工作地点：苏州` → 回填城市（10 条）
3. **岗位标题/部门里的城市**：`(深圳)`、`-上海-` → 回填城市（8 条）
4. **渲染页面**：岗位卡片里的城市/岗位名（85 条城市、111 条方向）
5. **入口页 HTML**：`2027届` 字样 → 回填届次（44 条）

代码里所有回填都带来源标注（写进 `notes`），可直接复核；拿不到的一律留空。
