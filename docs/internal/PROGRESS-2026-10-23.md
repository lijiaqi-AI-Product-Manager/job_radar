## 2. 这一阶段做了什么

**日历字段**
- 规范固化：`docs/CALENDAR-FORMAT.md` + `docs/DEVELOPMENT.md`（11 个字段、项目类型分条目、JD 规则、留空约定）
- 5 条补全通道（全部可复核）：
  1. 入口页 HTML：`20XX届` → 届次（44 条）
  2. Playwright 渲染：岗位卡片 → 方向/城市（方向 111 条、城市 85 条）
  3. 数据层投票：该公司 948/952 岗位都是 2027 届 → 届次（27 条）
  4. JD 明写工作地点 → 城市（10 条）
  5. 岗位标题/部门里的城市 → 城市（8 条）
- 字段完整度：25.0% → **38.0%**（人工条目）；按公司 59.9% → **60.7%**

**数据源**
- 北森旧版：新华保险（267 岗，城市 100%）
- Workday：英特尔（30）、辉瑞（200）、阿斯利康（240）
- Workday 适配器新增三种租户差异支持：`locationMainGroup` 分面、`Location_Country` 精确匹配、`China - 上海 - 上海` 城市写法

## 4. 公众号这条通道的结论

- 微信对**数据中心 IP** 返回「环境异常」验证页；GitHub Actions 与本地都拿不到正文
- 按铁律不绕过验证 → 公众号只作为**人工补充来源**，不自动化批量抓
- 代码保留：`scripts/wechat_parse.py`（能解析届次/网申时间/城市），人工贴 URL 即可用
