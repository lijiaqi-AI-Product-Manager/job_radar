# 阶段进展：可推广性打磨（2026-10-24）

接在 [PROGRESS-2026-10-23.md](PROGRESS-2026-10-23.md)（日历字段与数据源）之后，这一阶段解决的是
**「能不能对外推广」**：发布链路、国内镜像、文档、异常自愈。

## 1. 结果一览

| 项 | 之前 | 现在 |
|---|---|---|
| PyPI 发布 | 只能 `pip install git+https://…` | `publish.yml`（Trusted Publishing，无需 token）+ `docs/PUBLISHING.md`；仓库变量 `PYPI_ENABLED=true` 后推 tag 自动发 |
| Gitee 镜像同步 | 35MB 整文件上传 ~2 小时（贴 150 分钟超时线） | **2.6 分钟**（12MB 分片 × 3 并发） |
| 客户端走镜像 | 经常超时、回退 GitHub | **80 秒**拉完 55MB，自动合并 2+3 个分片 |
| `jobradar update` | 每次全量下载 55MB | 比对 Release sha256，**没变就 0 下载**；`--force` 可强制全量 |
| 本地库损坏 | 增量跳过 → 永远卡在坏库 | 跳过前 `PRAGMA quick_check`，坏了自动重下；`doctor` 给建议 |
| CI | ubuntu 3.12 + windows 3.12 | 再加 **ubuntu 3.11** 兼容性作业 + `concurrency` 取消过期运行 |
| 控制台编码 | 英文版 Windows 打印中文直接崩 | CLI 启动切 UTF-8(errors=replace) |
| MCP | `jobradar-mcp --help` 挂在 stdio | 有 `--help/--version`（帮助文本 ASCII） |
| 文档 | README 还写 0.9.0 / 134 家 / 99.9% | 全部对齐发布数据，并新增 CONTRIBUTING / SECURITY / issue 模板 / FAQ / 数据许可草案 / 文档索引 |
| 城市映射 | 英文名只有 27 条（Workday 源城市被卡） | **101 条**；Intel 90%→100%、辉瑞 75%→88% |
| 多地点岗位 | Workday `additionalLocations` 没读 | 已解析（辉瑞 60 岗里 5 个从"无城市"变"2 城市"） |
| 统计口径 | `stats` 490 vs README 494 | 统一为「有日历条目」/「有日历或数据」两种口径并写明 |

## 5. 怎么复现这一阶段的验收

```bash
uv run pytest && uv run ruff check src tests scripts
uv run python scripts/release_check.py --home ~/.jobradar
uv run python scripts/verify_gitee.py <本地 release 文件...>
JOBRADAR_MIRROR=gitee jobradar update --force     # 干净目录下
jobradar update                                   # 第二次应 0 下载
jobradar doctor                                   # 三库齐全、jd_text_match=1.0
```
