# 覆盖率天花板测算（2026-10-28）

目标清单 1,655 家（20 个行业 1,117 + 31 个省级行政区 808，去重后 1,655）。
当时已接入 577 家（35%），剩 1,078 家没有可抓入口。

这份文件回答一个问题：**在不碰 Moka 加密、不碰聚合站、不写死签名的前提下，覆盖率最高能到多少。**

## 怎么测的

`work/coverage_ceiling.py` 把每一家未覆盖目标按「已知证据」分类：

1. 先在 `work/careers_ats.jsonl`、`careers_ats2.jsonl`、`ats_findings.jsonl`、`careers_confirmed.jsonl`
   里找这家公司出现过的所有 URL / 主机 / 平台指纹；
2. 再按下面的优先级打标签：

| 类别 | 判定条件 | 含义 |
|---|---|---|
| `moka` | 证据里出现 `mokahr` | 招聘门户在 Moka 上，正文 AES 加密（合规红线，不碰） |
| `aggregator` | 只出现智联/前程/猎聘/BOSS/应届生等 | 只挂聚合站（红线，不碰） |
| `platform` | 出现 `zhiye.com` / `hotjob.cn` / `jobs.feishu.cn` / `myworkdayjobs` / `tupu360` | 平台入口已看到，只差建源（可做） |
| `self` | 有公司自有招聘页，但没识别出平台 | 要逐个看页面有没有 JSON 接口（可做但慢） |
| `unknown` | 一条线索都没有 | 不知道去哪抓（难） |

## 结果

| 类别 | 数量 | 占未覆盖 | 说明 |
|---|---|---|---|
| platform | 78 | 7% | 能补，但要逐家确认租户 |
| self | 444 | 41% | 能补一部分，每个站点要单独判断接口 |
| unknown | 431 | 40% | 省属国企/城商行居多，招聘信息多在国聘、地方人社或校园宣讲，没有公开可抓入口 |
| moka | 114 | 11% | 合规不碰 |
| aggregator | 0 | 0% | 已在前几轮被 Moka 判定吸收，或本来就走 Moka |

- 当前：**577 / 1,655 = 35%**
- 上限（platform + self 全部拿下且都能抓）：**(577 + 78 + 444) / 1,655 = 66%**
- 也就是说：**90% 在这个目标清单上不可达。** 不是工程投入不够，是分母里 546 家（Moka + 无入口）根本没有合规的抓取入口。

## 三条能真正抬高覆盖的路

1. **补 platform 的 78 家**：检索已经能按公司名问到门户（`work/company_name_search.py`），逐条探活 + `<title>` 定归属即可，风险低。
2. **self 的 446 家里挑「有接口」的**：多数是 SPA + JSON，和 gllue / Moka 的白标不同，需要一站点一判断；按 20% 命中估，约能再加 90 家。
3. **unknown 的 431 家**：需要把目标池的口径改成「有公开招聘入口的公司」，否则永远算不进分子。这一步是**改定义**，不是抓取，必须由需求方决定。

## 结论

- 指标上，35% 是「按平台捞人」这条生产线的真实产出；
- 若继续用现在这张 1,655 家的目标清单，工程上限是 66%；
- 如果只用「可合规覆盖的目标」（扣掉 Moka 与无入口），当前是 577 / 1,089 = 52%，天花板 100%（但分母换了，必须同时展示两个口径）。
