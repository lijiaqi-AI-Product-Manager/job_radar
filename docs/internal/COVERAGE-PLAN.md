## 2. blocked 判定：必然还是短暂？

判定方法：区分**频控型**（429/5xx/超时/限流 → 重试可解）与**凭证型**（401/403/no-auth/验证码/robots → 每次访问都相同）。
本轮对每家做了至少两次独立复测（间隔数分钟到数天、不同入口）：

| 来源 | 失败现象 | 复测 | 判定 | 依据 |
|---|---|---|---|---|
| 字节跳动 | POST 列表 405、空响应体 | 2026-10-20、10-22 两次，以及带/不带 CSRF、带/不带 Referer 共 5 次 | **必然** | 405 不是频控；GET 回落 SPA；SSR 的 `js-websiteInfo` 里没有 CSRF；页面部署 `verify.snssdk.com` 滑块 |
| 京东 | 页面预加载 `jcap.m.jd.com/requireCaptchaPc.js` | 历史 3 轮 + 本轮复核 | **必然** | 验证码是页面级前置，不是触发式频控；列表接口在验证码前无法确认 |
| 拼多多 | 前端完整验证码流程、robots 403 | 2 轮 | **必然** | 同上 |
| 百度 | 列表接口 `no-auth` | 2 轮 | **必然** | 需要登录态 |
| 华为 | 列表接口 403 | 2 轮 | **必然** | 匿名一律 403 |
| 快手 | `robots.txt: Disallow: /` | — | **政策禁止** | 不是技术问题，按 COMPLIANCE 不做 |
| 小米 | 无岗位列表 | 本轮复核 | **无数据可抓** | 官网只有项目/日程/新闻，投递走公众号 |

结论：**没有一个是「短暂」的**。唯一的例外是限流（429）——目前没有源处于这个状态，`crawl` 已有重试。

补充路径（对所有公司适用）：
- **官方公众号 / 官网公告**：岗位明细拿不到，但「什么项目、什么时候开、去哪投」可以人工核实后进 `calendar.db`——这是当前对字节/京东等已在做的事。
- **第三方聚合（牛客、OfferShow、实习僧）**：数据可能全，但来源不是官方、ToS 与再分发风险高，**按 COMPLIANCE 不做**。
- **官方合作/数据授权**：给招聘方发邮件申请公开接口或数据导出，是唯一能合法拿到验证码类站点数据的方式。

## 4. 平台优先：真正能把覆盖率拉起来的路

覆盖率瓶颈不是「某家公司抓不抓得到」，而是**这家公司用哪个 ATS**。一个平台适配器 = 几十到几百家公司。

| 平台 | 状态 | 覆盖量 | 下一步 |
|---|---|---|---|
| 北森 `*.zhiye.com` | ✅ 已做 | 189 → 191 家 | 持续发现租户（见下） |
| 北森旧版 | ✅ 已做 | 12 家 | 已收口 |
| Moka `*.mokahr.com` | ⛔ | — | 响应 AES 加密，按铁律不逆向 |
| **飞书 ATSX** | 🟡 侦察到接口 | 字节、蔚来、小鹏、理想、货拉拉… | **用 GitHub Actions 的 RENDER 抓一次真实 XHR**（本地沙箱不能跑浏览器） |
| 大易 / gllue | ⬜ 未侦察 | 中等 | 找到租户后按北森模式做 |
| 自研站 | 逐家 | 大疆/OPPO/荣耀/比亚迪/宁德… | 每家一次侦察 |

### 飞书 ATSX 的进展（2026-10-22）

- 确认**蔚来、小鹏、大疆**等用的是飞书 ATSX（`*.jobs.feishu.cn`；大疆还挂了定制域名
  `apply.careers.dji.com/campus-recruitment/dji/143359`），与字节同一套。
- 已找到公开接口：`GET /campus` → 200，SSR 数据在 `#js-websiteInfo`。
- CSRF：`POST /api/v1/csrf/token` → 200，返回 `{"data":{"token":…}}` 并下发 `atsx-csrf-token` cookie（**匿名可拿**，符合铁律 1）。
- 搜索：前端调用 `{base}/api/v1/search/job/posts`，但直接 POST 返回 **405/307**——说明还有一层签名/网关校验，必须看浏览器真实请求头与顺序。
  定制域名（大疆）返回的是另一套后端的 JSON 404（`connect.sid`/`csrfCk`），路径也不一样。
- **结论**：本地沙箱禁止命名管道，Playwright 起不来（`spawn EPERM`）；仓库已有的 `recon-probe` 工作流跑在 Actions 上，有浏览器，用 `RENDER`/`RENDERXHR` 抓一次即可拿到完整请求。这是下一步的最高杠杆动作。
