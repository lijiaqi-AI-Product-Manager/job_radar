## 失败原因与修复建议（按优先级）

1. **公司简称不匹配（neg-05，P0）**
   `--company` 只做公司全名的子串匹配。用户说「中核」「中船」「国寿」「中交建」，
   库里存的是「中国核工业集团」「中国船舶集团」「中国人寿」「中国交建」。
   建议：加一份 `taxonomy/company_aliases.yaml`（简称 → 全名），`search_jobs` 先解析别名再匹配；
   先写测试（别名命中、全名不受影响、无别名时行为不变）。

2. **过滤后为空没有提示（lookup-01 / lookup-07，P1）**
   腾讯校招（1025 岗）、长鑫校招（194 岗）的源**不提供届别**，`--grad-year` 必然为 0。
   SKILL.md 已要求"去掉过滤再查"，但 agent 很容易直接回答"没有"。
   建议 `search` 在过滤结果为空时返回 `hints`：例如"该源岗位没有 grad_year，去掉 --grad-year 有 218 个"。

3. **缺"按职类的新增统计"（trend-02，P2）**
   `diff` 只有事件流，需要按 `category` 聚合才能回答"最近哪类职位新增最多"。
   建议加只读查询（CLI + MCP 共用 `core/queries.py`），或在 skill 里明确说明需要两步。

4. **`compare` 不支持 `--text`（compare-04，P3）**
   "哪家最看重论文发表"必须读 JD 原文。建议 `compare` 支持 `--text`，或在 skill 里写清
   "先用 `search --text` 找候选，再 `show` 读原文"。

5. **阿里尚未采集（lookup-06 / compare-01，预期）**
   适配器 2026-10-22 合入，下一次 `daily-crawl` 起才有数据；届时应重跑这两题。

## 已知的数据事实（供后续判分参考）

- 腾讯校招 1,025 岗、全部无 `grad_year`（接口无该字段）；其中 `category=技术` 218 个。
- 长鑫存储校招 194 岗、全部无 `grad_year`，JD 原文也未提及届别。
- 「中国核工业集团」1,138 个校招岗中只有 1 个有城市字段——城市缺失是北森门户的结构性问题。
- 阿里 fixtures 实测：校招 458 + 日常实习 360 + 研究型实习 257。

## 结论

- 查询层与 skill 的"只用数据、不编造、区分没有/下架、说明时间"这几条在 30 题里都站得住。
- 真正影响体验的是**数据字段缺失**（届别、城市）和**公司简称**，不是回答规则。
- 下一轮优先做别名表与"过滤为空提示"，这两项能把 lookup-01/07、neg-05 从 ⚠️/❌ 变成 ✅。
